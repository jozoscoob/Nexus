# n8n 워크플로우 분류 설계 — 수집 · 정제 · 분석·평가 · 통합 (2026-11-19)

> 요청(승인자): n8n 워크플로우를 ①데이터 수집(웹 수집 포함) ②가공·정제 ③분석(여러 모델 비교·검증)과 평가 ④①~③ 통합으로 분류·설계.
> 산출: `docker/n8n/nexus_0*.json`(가져오기 가능) · 도식 `docs/architecture/n8n_workflows_categorized.drawio` · 생성기 `scripts/build_n8n_workflows.py`.

## 2. 설계 원칙 — 참고 자료에서 가져온 패턴

| 참고 | 가져온 것 | Nexus 적용 |
|---|---|---|
| n8n 템플릿 모음(n8n.io/workflows, awesome-n8n-templates) | 하위 워크플로우 모듈화(Execute Workflow + Execute Workflow Trigger), 오류 워크플로우, 메모(sticky note)로 단계 설명 | 01·02·03은 단독 실행과 호출 실행 모두 가능. 04는 호출만 담당 |
| crewAI · Mastra | 역할·단계 분리, 단계마다 명시적 입출력 | 단계별 runner 작업 = 정해진 명령만(임의 명령 불가), 결과 JSON으로 성패·소요 기록 |
| Dify · Langflow | 단계별 관찰 가능성(실행 추적 화면) | 실행 보고 HTML이 단계별 성패·소요·로그 꼬리·산출물 링크를 한 화면에 |
| LiteLLM | 모델 호출 단일 창구 | 외부 도구 호출은 runner HTTP 하나로 모음(n8n에 자격 증명 없음). Codex도 runner 안에서만 실행 |
| OpenHands · Letta | 코드 작업 에이전트·장기 기억 | 채용하지 않음 — 파이프라인 자동화 범위 밖. 장기 기억은 Obsidian 볼트 보기가 담당 |

새 플랫폼은 설치하지 않았다(Dify·Langflow 등 도입은 별도 승인 필요).

## 3. 검증 원칙

- **단계별 Codex 교차검증**(읽기 전용 샌드박스): 오늘 갱신된 산출물 + 그것을 만든 코드 + 단계 점검표를 넘긴다.
  - 수집: 필수 열·as-of 필드, 중복 키, 시점 역전·미래 발표일, 조용한 실패
  - 정제: ASOF 조인(available_at ≤ t), 값 충돌 즉시 실패, 목표 열 피처 혼입, 목표 계열 출처
  - 분석: walk-forward 누수, 화면 수치 ↔ 원천 표, 지표 산식, 확률 약속·구매 권고 문구
  - 결과: `reports/ops/codex_verify_{단계}_{날짜}.md`(로컬 전용)
- **실패의 가시성**: 수집 실패는 비치명(저장된 최신 데이터로 진행)이지만, 실행 보고·알림에서 숨기지 않는다. 마트 게이트는 fail-closed.
- **24시간 규칙**: 실행 보고는 24시간보다 오래된 결과를 '이번 실행 아님'으로 표시한다(과거 성공을 현재 성공으로 위장하지 않음).

## 4. 2026-11-19 첫 교차검증에서 고친 결함

| 단계 | 지적 | 조치 |
|---|---|---|
| 정제 | **저녁 마트가 값 충돌 136건으로 중단** — 같은 커넥터의 일자 스냅샷(11-17·11-19)이 같은 날짜에 다른 값(앞 스냅샷은 장중 미완성 봉) | 같은 계열 일자 스냅샷끼리 겹치면 최신 스냅샷 값 채택(서로 다른 계열·같은 파일 안 충돌은 계속 실패). 자체검증 통과 |
| 분석 | 범위 비교 EWMA 초기값이 첫 20일 수익률을 미리 봄 | 고정 사전값(일 1.5%)으로 시작 — 평가 시작(2012) 전 소멸 |
| 분석 | 기준선 백테스트의 락박스 경계에 채점일이 락박스 안인 예측이 섞임 | 채점일(t+h)이 락박스 시작 이전인 예측만 본 평가에 포함(정화) |
| 분석 | 성적표 '±폭'이 로그 폭의 절반이라 가격 대칭 범위로 오독 | 전체 로그 폭 표기로 변경 |
| 분석 | FHS 창 751쌍(명세 750) | 750쌍으로 수정 |
| 정제 | 세션 종가 보고서의 PASS 기준 표가 실제 판정 기준과 다름 | 실제 적용 기준(중앙값 ≤0.25%·괴리 2% 초과일 ≤2%)으로 표기, 구 기준은 참고로 분리 |
| 수집 | GDELT 성공 쿼리 0개여도 '[완료]' 출력 | 0개면 경고로 출력 |

판단이 필요한 지적(수정 보류): 예보 계열의 리드별 중복(마트에서 의도적으로 제외 중) · 관세청 증분 파일의 넓은 형식 · 장중 확정 지표의 익일 available_at(설계상 의도) · 부분 수집 실패의 종료 코드 정책 · 목표 계열이 yfinance 정산가 표본이며 Databento와 교차검증으로 채택한 점(공식 정산가 원천 확보는 별도 과제).

## 5. 운영

- 가져오기: `docker exec docker-n8n-1 n8n import:workflow --input=/workflows/<파일>.json`(파일별 — 폴더 가져오기는 옛 파일까지 다시 넣음).
- 켜기: n8n 화면에서 '04 통합'·'주간 정비'만 활성화하면 된다(01·02·03은 호출용이라 켤 필요 없음).
- 단독 확인: 각 워크플로우 화면에서 'Execute workflow'.
