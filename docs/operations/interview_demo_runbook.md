# 시연 런북 — Docker + n8n로 '수집 → 정제 → 분석·평가 → 최종 산출물'까지 (2026-11-20)

> 목적: 실행 중인 Docker 컨테이너와 n8n 워크플로우가 최종 산출물(실행 보고·G2 화면·G1 브리프·교차검증 보고)을
> 끝까지 만들어 내는 과정을 5분 안에 보여 준다. 수치는 시연 당일 화면 값을 그대로 읽는다(이 문서에는 싣지 않음).

## 1. 무엇을 만들었나 (진행 단계)

| 단계 | 내용 | 결과물 |
|---|---|---|
| ① 실행 환경 | 개인 노트북 Docker: `runner`(Python 3.11 + 데이터 작업 서버 + Codex CLI) · `n8n`(오케스트레이터). runner는 정해진 작업만 HTTP로 실행(임의 명령 불가) | `docker/compose.yml`, `docker/jobs.py` |
| ② 수집 | 무료 커넥터 12종(거시·기상·해상·지정학·가격) + 시세 + 웹 수집 + RSS·뉴스. 모든 행에 as-of 필드(event_time·available_at) | `data/raw/*.parquet`(저장소에 올리지 않음) |
| ③ 정제 | 수동 업로드 파서 → 시점 정합 마트(DuckDB ASOF JOIN, available_at ≤ t) → 값 충돌 시 즉시 실패 | `data/gold/feature_mart.parquet` |
| ④ 분석·평가 | 참고 범위 방식 5종을 같은 walk-forward 조건에서 비교 → 기준선 성적표 → G1 변수 중요도·브리프 → G2 화면 | `reports/...` HTML |
| ⑤ 교차검증 | 단계마다 Codex가 산출물과 코드를 읽기 전용으로 점검 → 결함 7건 발견·수정 | `reports/ops/codex_verify_*.md` |
| ⑥ 지식 관리 | 용어·인과 사슬·문서 요지를 Obsidian 볼트로 매일 07:00 동기화 | Google Drive 'Obsidian Vault/Nexus' |
| ⑦ 통합 | n8n: 01 수집 · 02 정제 · 03 분석·평가 · 04 통합(하위 워크플로우 호출) + 00 시연(빠른 실행) | `docker/n8n/*.json` |

## 2. 사전 점검 (시연 30분 전)

1. Docker Desktop 실행 → 컨테이너 확인: `docker ps` 에 `docker-runner-1`, `docker-n8n-1`이 `Up`.
   멈춰 있으면 `docker compose -f docker/compose.yml up -d`.
2. n8n 열기: http://localhost:5678 → 워크플로우 목록에 'Nexus 00 시연(빠른 실행)', 'Nexus 04 통합 파이프라인'.
3. 최근 산출물 열어 두기(브라우저 탭 4개):
   - `reports/ops/pipeline_run_latest.html` (실행 보고 — 최종 산출물)
   - `reports/g2_preview/g2_preview_latest.html` (G2 화면)
   - `reports/pipeline/g1_daily_brief_*.html` 최신 파일 (G1 브리프)
   - `reports/ops/codex_verify_process_*.md` (교차검증 보고)
4. 도식: `docs/architecture/n8n_workflows_categorized.drawio`(draw.io로 열기).
5. (선택) 볼트: Obsidian에서 'Obsidian Vault' 열고 그래프 보기.

## 4. 강조할 점

1. **시점 정합(as-of)**: 모든 값에 '언제 알 수 있었나'(available_at)를 붙이고, t일 계산에는 그 이전에 공개된 값만 쓴다 — 백테스트가 실제보다 좋아 보이는 누수를 구조적으로 막음.
2. **fail-closed 게이트**: 같은 지표·같은 날짜에 값이 둘이면 자동 선택하지 않고 멈춘다. 이번 교차검증에서 실제로 작동했다.
3. **방법 비교 후 교체**: 감으로 바꾸지 않고, 같은 walk-forward 조건에서 적중률·폭·분위 손실·안정성을 비교해 결정했다. 원안(컨포멀)은 지금 범위를 더 넓혀 기각했다.
4. **교차검증의 자동화**: 사람이 다 볼 수 없는 단계 산출물을 별도 AI가 읽기 전용으로 점검 → 사람은 판정만.
5. **장애에 강한 구조**: 수집이 실패해도 저장된 최신 데이터로 끝까지 가고, 실패는 실행 보고·알림에 드러난다.

## 5. 방법론 요약

| 항목 | 방법 |
|---|---|
| 데이터 계약 | `price_date · indicator_code · value` + as-of 5필드(event_time · release_time · available_at · source_vintage · ingested_at) |
| 마트 | DuckDB ASOF JOIN(거래일 × 지표), 신선도 상한, 값 충돌 하드 실패, pandas 독립 재계산 대조 |
| 목표 계열 | CME 대두유 근월 정산가 — Databento 일봉과 교차검증한 계열만 사용 |
| 참고 범위 | 중심 = 현재 정산가, 폭 = 최근 변동성(EWMA) × √기간 × 정규 분위. 2012~2025 walk-forward로 비교·선정 |
| 평가 지표 | 적중률(coverage)·폭·pinball(분위 손실)·위/아래 이탈률·폭 일변동, 스트레스 구간(2012·2018·2020·2022·2025) 분리 |
| 교차검증 | 단계별 Codex 읽기 전용 검토(산출물 + 생성 코드 + 점검표) |
| 문구 규칙 | 과거 관측 요약만 — 확률 약속·구매 권고 금지, 판단은 담당자 승인 |

## 6. 현장에서 문제가 생기면

| 증상 | 조치 |
|---|---|
| 인터넷이 안 됨 | '00 시연'은 수집 2종만 새로 받는다. 실패해도 비치명이라 나머지는 저장 데이터로 끝까지 실행된다. Codex 단계만 건너뜀(성공 처리) |
| n8n 화면이 안 열림 | `docker compose -f docker/compose.yml up -d n8n` 후 1분 대기. 그래도 안 되면 미리 열어 둔 산출물 탭으로 진행 |
| 워크플로우가 409(다른 작업 실행 중) | runner는 한 번에 한 작업만. 진행 중인 작업이 끝나면 다시 실행 — 그동안 기존 산출물 설명 |
| 마트 단계 실패 | 게이트가 작동한 것 — 실행 보고의 로그를 열어 원인(값 충돌 지표명)을 보여 주고, 직전 정상 산출물로 설명 |
| Codex 로그인 만료 | 교차검증 단계가 건너뜀으로 끝난다(비치명). 이미 생성된 교차검증 보고를 보여 준다 |
| 컨테이너가 멈춤 | `docker compose -f docker/compose.yml restart runner` (약 10초) |

## 7. 재현 명령

```
docker compose -f docker/compose.yml up -d
docker exec docker-n8n-1 n8n import:workflow --input=/workflows/nexus_00_demo.json
```
n8n 화면에서 실행하거나, 명령줄로: `docker exec -e N8N_RUNNERS_BROKER_PORT=5699 -e N8N_PORT=5699 docker-n8n-1 n8n execute --id=nexusDemo01`
