# Typst 도입 필요성 판단 (2026-11-19)

> 요청(승인자): Typst가 이 프로젝트에 필수인지 판단하고, 필수라면 역할을 정해 다른 도구와 비교한 뒤 반영할 것.
> 결론: **현시점 필수 아님 — 도입하지 않음.** 월간 인쇄판을 따로 디자인하기로 할 때만 다시 검토함.

## 1. 지금 PDF가 어디서 쓰이는가 (실측)

| 산출물 | 현재 형식 | PDF 경로 | 상태 |
|---|---|---|---|
| G1 일일 브리프(v6) | Python이 만드는 단일 HTML | 없음 — 화면·메일 열람 | 운영 |
| G2 미리보기 | 단일 HTML | 없음 | 운영 |
| G1 변수 중요도 보고서 | HTML(+PDF 시도) | `weasyprint` 있으면 변환, 없으면 건너뜀 | **로컬 runner에 weasyprint 미설치 → PDF 생성 안 됨** |
| 연구 문서 PDF | `scripts/generate_research_pdf.py`(weasyprint) | 수동 | 사용 드묾 |

핵심 산출물은 이미 HTML이며, 인쇄는 CSS `@page`로 A4 2쪽을 맞추는 설계(G1 v6 제안서 §3)로 충분함. PDF가 필수인 정기 산출물은 현재 없음.

## 2. 후보 비교

| 기준 | weasyprint(기존) | Chromium 인쇄(Playwright) | **Typst** | Quarto | LaTeX |
|---|---|---|---|---|---|
| 같은 HTML/CSS 재사용 | ✅ 그대로 | ✅ 그대로 | ❌ 별도 `.typ` 템플릿 | △ md→HTML/PDF(PDF는 LaTeX·Typst 경유) | ❌ 별도 |
| 한국어 조판 | 시스템 폰트 지정 필요(A-056) | 브라우저 수준 | 양호(폰트 내장 가능) | 엔진 따라 다름 | 설정 부담 큼 |
| 이미지 추가 무게 | pip + pango 라이브러리 | Chromium 수백 MB | 단일 바이너리 약 40 MB | 설치 무거움 | 수 GB |
| 인쇄 품질·쪽 제어 | 보통 | 보통(화면 그대로) | **우수**(쪽·각주·표 분할) | 우수 | 최고 |
| 유지 비용 | 템플릿 1개 | 템플릿 1개 | **템플릿 2개(HTML+Typst) 이중 관리** | 별도 체계 | 별도 체계 |
| 라이선스 | BSD | Apache-2.0 | Apache-2.0 | MIT 계열 | 다양 |

판단 근거:
- Typst의 장점(인쇄 조판 품질)은 **인쇄 전용으로 따로 디자인한 문서**에서만 살아남. 지금처럼 화면용 HTML을 인쇄하는 용도에는 이점이 없음.
- 도입 시 같은 내용을 HTML과 Typst 두 템플릿으로 유지해야 함 — 수치 불일치 위험과 작업량이 늘어남.
- 기존 경로(weasyprint)는 같은 HTML/CSS를 그대로 PDF로 바꾸므로, PDF가 필요해지면 **weasyprint를 runner 이미지에 넣는 것이 최소 변경**임.

## 3. 결정

- **도입하지 않음.** 일일 G1·G2는 HTML 단일 경로 유지, 인쇄는 CSS `@page`.
- PDF가 정기 산출물로 필요해지면 1순위는 weasyprint를 runner 이미지에 설치(라이브러리 목록 등재 후), 같은 템플릿을 재사용.
- Typst는 **월간 심층판을 인쇄 전용으로 따로 디자인하기로 결정할 때** 재검토 후보로만 남김(0.15.x, Apache-2.0, 도커 단일 바이너리).

## 4. 결정 필요
- G1 변수 중요도 보고서의 PDF가 지금 생성되지 않는 상태(runner에 weasyprint 없음)를 그대로 둘지, weasyprint를 이미지에 넣을지.
