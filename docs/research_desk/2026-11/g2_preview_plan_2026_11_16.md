## 0. 한 줄 결론

- **G2는 이미 정의돼 있다**(CONFIRMED — README §QR·modeling.md·C-03 §2): 대두유 CBOT 정산가의 1·5·20·60거래일
  확률 가격 범위(P10/P25/P50/P75/P90, 50·80·95% 구간). 새로 정의하지 않는다.
- **목요일 목업 = 백테스트 전용 Preview**: 기준선 3종(기존 코드) + Quantile LightGBM + 등각 보정(CQR) → 과거 표본 성적표와
  범위 차트 1장. EGARCH-X·SARIMAX는 시간이 남으면 넣는 스트레치.
- **막는 것은 모델이 아니라 데이터 신선도와 실행 표면**(CONFIRMED): 목표변수 원천 CSV는 2026-08-12에서 멈췄고
  (`data/raw/Databento/GLBX.MDP3/ZL_ohlcv-1d_2010-06-06_2026-08-12.csv`), 학습 입력 마트(parquet)는 Actions에서만 만들어졌는데
  Actions는 2026-09-30 이후 실행이 없다. → **Docker 실행 + n8n 스케줄로 대체하는 것이 오늘의 첫 작업**이다.
- **신규 유료 구매 없이 가능**: 이미 결제 중인 Databento로 목표변수·대두박·대두를 갱신하고, 나머지는 공개 데이터로 채운다.
- **승인 필요 6건**(§4) 중 2건은 승인자 확인으로 해소(D-2 로컬 Docker·D-4 parquet 정본 — 2026-11-16 퇴사·개인 노트북 확인).
  **오늘 남은 2건**: ①동결(DQ-22) 부분 해제 ②Databento 인출 범위·상한.
- **시장 구조(ABCD·COFCO·Wilmar) 반영은 축소가 아니라 확대**(§6): 철회한 6건은 전 회사 IT 항목뿐이고 구조 지표·회사별 자료는
  그대로다. 목요일 모델에 구조 지표를 후보 피처로 넣고, 목요일 이후 공시·IR·기사 기반 '기업 설비 추론' 층(S8)을 붙인다.

## 1. PM 관점 전체 방향 (C-01)

**전제 사실**(CONFIRMED): 2026-09-13 승인(DQ-22)으로 9/10 'G2 Preview'는 'G2 준비 패키지 동결'로 재정의됐다. 재개 조건 4종 —
①승인된 Databento 3종(ZM·ZS·옵션) 반입 ②TE 일별 밀도(DQ-21, 9/13 종결) ③운영 표면 확정 ④인수 측 해석 훈련 — 중 ①은 아직 미충족이고, ③은 개인 노트북 Docker로 확정됐다(D-2 해소).
사내 인프라(AWS 이관·Snowflake·방화벽 허용 목록) 전제는 퇴사로 무관해졌다(2026-11-16 승인자). 따라서 이번 목업은 조건 충족이 아니라 **승인자 판단으로 '선택지 B(백테스트 전용 Preview)'를 여는 것**이며, 결정
D-1로 기록한다.

**원칙**
- **날짜 고정·범위 가변**: G2 정의, 시점 정합(as-of), 평가 규칙(지평·스트레스 구간·lockbox)은 고정한다. 줄이는 것은 모델 구성
  요소 수뿐이다(C-03 §0 "평가 규칙은 결과를 보기 전에 잠근다").
- **주장 범위 고정**(A-191 유지): 화면 문구는 "과거 표본 성적표·참고 범위". 상승확률·임계가격 초과확률은 표시하지 않는다.
  조달 판단에 쓰지 않는다는 문구를 상시 표시한다.
- **기존 자산 재사용**: 기준선 백테스트(`src/evaluation/band_backtest.py`), 마트 빌더(`src/features/build_feature_mart.py`),

  그대로 쓴다. 새로 쓰는 코드는 Docker·n8n 연결, Databento 확장, 신규 무료 커넥터 2종, Champion 1개 파일뿐이다.

**성공 기준(목요일 검증 가능)**
1. 목표변수 `CBOT_BO_CLOSE`가 2026-11 최근 거래일까지 갱신되고 세션 종가 검증기 PASS
2. 마트 재생성, as-of 위반 0건, C-03 §6 진입 게이트 통과(목표 ≥98%·핵심 피처 ≥85%·DQSOps ≥0.70·available_at 100%)

**단계별 관점이 확정한 세부**
- **MLOps(C-04)**: n8n이 Python 작업을 부르는 방식은 "n8n 이미지에 Python을 넣고 Execute Command 노드로 저장소 스크립트 실행"이
  가장 단순하다. Docker 소켓을 n8n에 마운트하는 방식은 호스트 전체 권한을 넘기므로 쓰지 않는다. n8n 2.x는 Execute Command 노드가
  기본 비활성이라 환경변수로 켜야 한다(INFERENCE — 설치 버전에서 확인). 작업은 모두 비치명·로그 한국어 규칙 유지.
- **데이터 품질(C-08)**: 마트가 비면 통과로 처리하지 않는다(A-108 fail-closed 유지). 신규 커넥터는 `attach_asof()`를 거쳐야 마트에
  들어간다. CFTC COT는 화요일 기준·금요일 15:30 ET 공개라 `available_at`=금요일(+장 마감 이후이므로 1일 지연).
- **EDA(C-06)**: 8~11월 신규 구간의 이상치·결측 점검을 S2 직후 1회. 캡핑은 데이터 오류에만(M-010).
- **데이터 과학(C-03)**: 목표일 안에 Champion 4단 전체(2~3주 추정 — R-038)는 불가. LightGBM+CQR이 범위 폭과 레짐 붕괴(60일
  62%, 2020 27%, 2025 22%)를 개선하는지가 목업의 핵심 질문이다. 개선이 없으면 그 결과를 그대로 보고한다.
- **코드 리뷰(C-05)**: 랜덤 분할·전체 시계열 일괄 전처리·피처 선택의 학습 창 밖 수행을 차단 항목으로 본다.
- **보고·시각화(C-07)**: G1 브리프 디자인 토큰 재사용, 외부 라이브러리 없이 서버측 SVG. "확률"이라는 단어는 성적표의 포함률에만 쓴다.
- **상품 분석(P1-01)**: 압착 마진(ZL×11 + ZM×2.2 − ZS)은 대두 복합체의 대표 구조 변수 — ZM·ZS 갱신을 S1과 묶는다.
- **공급망(P1-04)**: 도착가 환산은 '참고 범위' 지위 상속(A-191). basis·운임 실측이 없으므로 목업에서는 1줄 각주 수준.

### 6.2 사실 정정 — 독점이 아니라 '집중된 과점'
선박 실거래 약 11만 건 분석(Wilson, AEPP 2025 — A-243): 대두 수출 상위 4사 점유 45%, 7사 코어(ABCD + Viterra·CHS·COFCO) 45%,
COFCO가 도착 기준 1위. 흔히 인용되는 'ABCD 70~90%'는 매출 합산이라 물량 점유와 비교할 수 없다(NOT COMPARABLE).
**차별점 주장은 그대로 유효하다** — 다만 근거를 '독점'이 아니라 '소수 기업이 압착·항만·선적 병목을 쥔 과점'으로 세워야
외부 검토에서 반박당하지 않는다. 모델 관점의 함의도 다르다: 독점이면 가격 결정자 1명을 추적하면 되지만, 과점에서는
**7사의 설비 증감·압착 마진·헤지 포지션**이 공급 측 가격 압력의 관측 가능한 신호다.
